# C-2 USB Bulk Transfer Spec (MVP v0.2)

## Goal
C-1 で構築した DMA リングバッファからデータを取り出し、USB Bulk エンドポイントで
ホストへ連続転送する。ホスト側は `capture.py` で受信し、連続サンプルをファイルへ保存する。  
DMA 側の実装を保持しつつ、USB 送信へ差し替え可能な I/F を明確化する。

## Scope (MVP)
- 1ch / 12MHz 相当のサンプルを USB Bulk 転送
- USB: Device mode / Bulk IN (device → host)
- USB class: vendor specific（CDC/MSC は使わない）
- 送信データは Raw サンプル (ブロック単位) のみ
- `capture.py` は受信・保存・簡易レート計測のみ

## Non-Goals
- 複数チャネル・デコード・HW トリガ条件
- 圧縮・可変長パケット・USB 省電力
- GUI 表示（C-3 で実施）

## USB Interface
### Endpoints
- EP0: Control
- EP1 IN: Bulk (device → host)
- EP1 OUT: 未使用（将来の制御用に予約）

### Packet / Transfer
- Max packet size: 512 bytes (High-Speed) / 64 bytes (Full-Speed)
- Transfer unit: `BLOCK_BYTES` のバッファ単位
- 送信は `BLOCK_BYTES` を基準に、USB packet 境界で分割

## Data Path (概念)
[DMA Ring Buffer] -> [C-2 Queue Pop] -> [USB Bulk IN] -> [capture.py] -> [bin file]

## Block Interface (C-1 互換)
DMA リングバッファから取り出すブロック I/F を定義する。  
C-2 は DMA 実装に依存せず、この API のみを利用する。

### Producer (DMA)
- `completed_ring_push(block_index)`
- `completed_blocks++`
- `overrun_count++` (full のとき)

### Consumer (USB)
- `bool capture_pop_block(uint32_t* out_index)`
- `void capture_mark_consumed(uint32_t index)`
- `uint8_t* capture_block_ptr(uint32_t index)`
- `uint32_t capture_block_size()`

## Host Tool (`capture.py`)
- USB Bulk IN のみ受信
- CLI 引数:
  - `--output <file>` 保存先
  - `--seconds <n>` 収集時間
  - `--bytes <n>` 収集バイト数
- ログ:
  - 受信バイト数
  - 実効レート (bytes / elapsed)

## Logging (minimum)
- `usb_tx_blocks` : USB へ送信したブロック数
- `usb_tx_bytes`  : 総送信バイト数
- `usb_tx_drop`   : 送信できずに破棄した回数

## Test Plan (MVP)
1. USB 接続時に `capture.py` が認識できること
2. 連続 10 秒の受信が可能なこと (転送断なし)
3. `usb_tx_blocks` が DMA `completed_blocks` と一致すること
4. `usb_tx_drop` が 0 もしくは検出できること
5. 受信レートが概算で 12MHz 相当に近いこと

## Acceptance Criteria
- DMA リングバッファ → USB 送信が連続 10 秒以上動作する
- `capture.py` で raw バイナリ保存が可能
- C-3 の GUI へ差し替え可能なホスト側 I/F を保持
